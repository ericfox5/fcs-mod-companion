# Roster stride inventory: what a 100-player roster cap would have to change

Status 2026-11-06 (night): **checkpoint 1 passed in game** (stride 100: the console loaded a re-keyed dynasty, played a
game, advanced, and uploaded a stride-100 file with PLAY kept at 13,000 rows). **Checkpoint 2 passed in game (2026-11-06 evening):**
the dynasty roster grows to 100 (99 slots) while games dress the first 70 slots, because the in-game side is 2 x 70 by
object layout; Duquesne and Georgetown at 99 played and survived the console's advance and upload (file 333). See "Stage 2 state" at the end.

The game encodes a player's team in his id: `PGID = TGID * 70 + slot`, slot 0..69, and every team carries 69 players
(slot 69 stays free). Raising the cap to 100 means a new stride (100) in the executable, in every save/dynasty/package
file, and in every tool that assumes 70. Generated by `spike/blaze/tools/roster-stride-inventory.py` over the decrypted
1.02 `EBOOT.elf` (full CSV with per-site evidence: `spike/blaze/private/roster-stride-inventory.csv`, gitignored).

## Data files

| file | table | rows / max | bytes/row | note |
|---|---|---|---|---|
| roster saves (STABLEV1, FCSMODNAME) | PLAY | 8694 / 9100 (= 130 x 70) | 112 | alloc 6 (fixed): the file holds all 9100 slots |
| dynasty file (DYNASTY-2) | PLAY | 8832 / 9100 | 120 | same layout, 3.87 MB used of the 0x7e5000 (8,278,016) console buffer |
| console `.team` package (locker) | PLAY | 69 / **70** | 116 | one zlib stream inflating to exactly 50,000 bytes: dbSize 45,220, 21 tables |
| `.team` package | CUTP / PINP / CAMW | 0 / 70, 0 / 840 (= 12 x 70), 0 / 200 | 4 / 16 / 8 | other per-roster tables sized from 70 |
| roster save file | | fixed 1,433,600 bytes (`0x15e000`) | | code site `0x3b46a0`; STABLEV1 has ~113 KB spare |
| dynasty DB buffer | | `0x7e5000` | | code sites `0x335828 0x336260 0x3362ec 0x3b0cbc` |

- PLAY at 100 per team: roster save 13,000 x 112 B = 1,456,000 B of PLAY alone, so the DB (1,320,160 B today) grows to
  about 1,757,000 B and no longer fits the 1,433,600-byte save buffer. The dynasty buffer has room (about 4.4 MB used).
- `.team` package with PLAY max 100: +3,480 B gives dbSize 48,700 of 50,000 (1,300 B spare). CUTP (70) and PINP (840)
  would also move if they are per-slot tables.
- Dynasty file: `ncaa-bridge roster grow` on DYNASTY-2233 re-keys 46,025 PGID cells across 27 tables (every PS*/S*
  stat table, DCHT, HEIS, AAPL, MCOV, INJR, PLAC, PRST, TRAN, PLSU ...), grows PLAY to 13,000 and lands at dbSize
  5,173,832 (3.1 MB spare). It also flags RCTN (max 8820 = 126 x 70) and SOFF (max 1750 = 25 x 70) as tables sized
  from the stride that are not grown automatically.
- PGID is a 16-bit field in every table that has it. At stride 100 the ids of teams above TGID 655 overflow; the FCS
  mod uses TGIDs up to 400 (the online copies), so the real rosters fit, but the sentinel 65535 and anything the game
  re-keys into high unused team slots (NOTES 2026-11-02: departed players go to "team 0" and TGIDs 116..123) must be
  mapped by arithmetic, not by the PLAY row's TGID.

## Executable (code segment 0x10000..0x1bc26e8)

| class | what it is | sites | with PGID/TGID/DB-query evidence in the function | dynasty region 0x42xxxx-0x53xxxx | engine region 0xa0xxxx-0xb2xxxx |
|---|---|---|---|---|---|
| div-mulli | `(x+1) * 0x7507 >> 21` = PGID / 70 | 8 | 7 | 7 | 1 |
| div-magic | `mulhwu 0xD41D41D5; subf; srwi 1; add; srwi 6` = x / 70 | 101 | 100 | 100 | 1 |
| mul-shift | `slwi 5; add X x3; add (double)` = x * 70 (pattern hit) | 301 | 114 | 110 | 57 |
| limit-li | `li rX,70` | 132 | 46 | 16 | 15 |
| limit-cmp | `cmpwi/cmplwi rX,69\|70` | 358 | 39 | 16 | 33 |
| size-const | 50000 / 0x7e5000 / 0x15e000 materialised | 25 | 10 | 0 | 0 |

- mul-shift: 7 feed a DB query call and 6 a compare within 24 instructions; 288 are unresolved by that simple data-flow
  test, 114 sit in functions that also reference PGID/TGID or call the DB layer. The run `0xb1f4c8..0xb20a24` (60 hits
  0x7c apart) is one unrolled block outside the roster code.
- limit-li: 18 pass 70 beside a stack buffer to a call (70-entry stack arrays: `0x4e8440` with two 280-byte arrays,
  `0x462044`, `0x1b6c68`, ...). limit-cmp: 86 bound a backward loop.
- League package creation `0x8ae38`: `bl 0x8a994(this, 'LEAG', 'PLAY', 70)` then `('LEAG', 'DCHT', 91)`; the other
  package tables (CUTP 70, PINP 840, CAMW 200) are created the same way nearby.
- Engine: `0xa94bac` computes slot = PGID - (PGID/70)*70 and adds 70 for the away team (0..139 index); `0xa23c84` and
  `0xa23cb0` index the same 140-entry structures. These are fixed-size home/away arrays.
- Script bindings `GetIsCreateAPlayerTeamRosterFull` / `GetTeamRosterSize` (descriptors `0x1c15b28` / `0x1c16c38`,
  functions `0x87d70c` / `0x88ac24`) read the cap for the UI; the roster-management cut logic compares the count with
  70 at `0x5045b8`.
- 210 functions carry at least one evidenced site; the busiest are `0x445aec` (12), `0x5151a8` (10), `0x4a85c8` (9),
  `0x2d7bc4` (7), `0x484508` (6), `0x4a7b6c` (6).
- Already patched: `0x45396c` (`mulli r9,r3,0x7507`) sits inside the All-Conference crash fix window and would be
  re-emitted by that patch's generator.

## What a Stage 2 patch would do (mechanical parts)

| site class | replacement | fits in place |
|---|---|---|
| div-mulli | `mulli rD,rA,0x51EC` + keep `srwi 21` (exact for ids below 43,478; max real id at stride 100 is 40,099) | yes, one word |
| div-magic | `lis 0x51EB; ori 0x851F; mulhwu; nop; nop; nop; srwi 5` (x / 100 for any 32-bit x) | yes, same length |
| mul-shift | `mulli rR,rX,100` + 4 nops, or `slwi 6 / slwi 5 / add / slwi 2 / add` when X must stay intact | yes, five words |
| limit-li / limit-cmp on counts | `li 100` / `cmpwi 99\|100` | yes, one word each; each needs classification |
| package creation | `li r6,100` at `0x8ae38` (+ CUTP/PINP if per-slot) | yes; 1,300 B spare in the 50,000-byte buffer |
| roster save size | `0x15e000` at `0x3b46a0` -> at least 0x1b0000 (the PS3 save directory also has to allow it) | one site, but the save-data size is also in PARAM.SFO/PFD |

## What is not mechanical (the risk)

- Stack arrays of 70 entries (18 `limit-li` sites pass 70 beside a stack buffer): each needs a bigger frame (`stdu`
  size, every offset above the array) and the 70 -> 100 count, per function.
- The engine's 140-entry home/away structures (`0xa94bac`, `0xa23c84`, ...): sizes live in struct layouts, not in
  one constant; the number of such structures is unknown until each use is traced.
- 288 multiply candidates and ~400 limit sites need a per-site decision; a wrong one breaks something unrelated.
- Paths that are hard to exercise end to end: offseason re-keying into free slots, recruit signing, Create-a-Player,
  injuries/cuts at 70, the online `.team` round trip, and the PS3 save-data size limits.

Estimate: several days of reverse engineering plus one in-game checkpoint per step (Stage 2 order in the plan: divisions
and confirmed multiplies -> limit/loop sites and the roster-size helpers -> `.team` package -> save sizes -> stack and
engine arrays -> offseason/recruiting), with a real chance of residual crashes in untested paths.

### Checkpoint 2 (2026-11-06 night): capacity entry, 70 dress

The in-game engine is 140 players (2 x 70) by layout: PLGA/DCGA rows, the player pool (0xa23c1c), objects with
140-entry arrays at fixed offsets (0xded90, 0xdea2c), a 140-entry stack array (0x4e4bf8), the +70 away offsets, the
'MULT' table, the recruiting UI's 70-slot per-team lists. Growing those means re-laying out compiled objects, so the
design is: **dynasty roster up to 100 per team; a game dresses slots 0..69** (the PLAY->PLGA and DCHT->DCGA copies keep
`base .. base+70`); slots 70..99 are reserves.

Second entry **"FCS mod: 100-player rosters (capacity)"** (`roster-stride-patch.py --capacity --cut 90`, 101 words,
requires the stride entry): 81 `base + 70` range ends -> `+100` in dynasty functions (19 kept at 70 where the
function touches an in-game `..GA` table, found as a 4CC immediate or inside its SQL strings), 8 roster-limit words
(see "Cut to 90" below), and the team-management module's six per-player arrays (12/14/27/4/2/2 bytes x 70) -> x100. Known limits left: the `.team` package's PLAY max 70 (creation
site not found; keep the member's own team at 70 or fewer until it is), CUTP/PINP in the package, the 70 player heads
per team, the recruiting UI lists. PS3 ELF with everything: `...-jersey0-roster100.elf` (`--roster-stride --roster-capacity`).

Test vehicle: `ncaa-bridge od players --did N --team "Abilene Christian" --fill 100` queues generated reserves (copies of
the team's own players by position, ratings 40, free jersey numbers from 0) through the dynasty-file copy; `od players`
alone shows what is queued, `--clear` drops it. A stride-100 team fills 99 slots (the game's one-slot margin, 69 of 70,
carried over; the capacity entry's "roster full" check is `>= 99`), and a transfer keeps his old team's PGID, so the
fill is bounded by the team's free slots, not its player count. Order matters: enable both roster entries in RPCS3 before the console
loads a file with a 100-player team.

### Cut to 90 (2026-11-06 night): the in-season limit

Eric's rule: teams keep 90 in the preseason and regular season, grow past it in the offseason (recruits, transfers)
and the Cut Players week trims them back to 90. Where the game's 70 lived (all in the capacity entry, `--cut N`):

| site | what | word |
|---|---|---|
| `0x5045b8` in `0x5041e4` (the offseason stage "Holding Team Tryouts / Evaluating Players / Cutting Players") | per team (cursor over TEAM where type = x): rows of the dynasty's CLST cut-list table in the team's PGID range (or MCTP = team) `> 70` hands the team to the auto-cut, else its cut list is cleared | `cmplwi r3,70 -> 90` |
| `0x5031ac` in the auto-cut `0x502cf8` | after a per-position pass (keeps the position's quota from the coach-style tables, best MIOP first) the final pass keeps players by MIOP until `r22 = 70 - (two special-position keeps)` are kept; the rest of the list is cut | `li r22,70 -> 90` |
| `0x266710` (TeamAdapter vtable `0x189ee48` + `0x3c`) | the script binding `GetMaxTeamRosterSize` is a stub returning 70: the "N / 70" and "must cut" figures of the Flash cut screens | `li r3,70 -> 90` |
| `0x1f1360` | `GameCheckRosterCutState` outside dynasty (roster management): POCH rows per team `> 70` | `-> 90` |
| `0x17eda0`, `0x1849d4`, `0x2529ec` | the roster editor's room / add / full checks on the `0x4ed494` team count (also `GetIsCreateAPlayerTeamRosterFull`) | `< 90`, `< 90`, `>= 89` |
| `0x50217c` | the free-slot search that places a new row (recruit signing) | stays `< 100` |

Not roster limits (checked and left alone): `GetNumScholarshipsRemaining` = 25 per class minus `TEAM.SDUR`
sanctions (`{25,15,10,5,0}[SDUR]`), minus the season's transfers in (TRAN rows in the team's range), minus commits
(RCPR) — recruiting is never bounded by roster room, so an offseason roster is `90 - departures + up to 25`, and the
PGID range (99 slots) only overflows when fewer than 16 players leave (the game then re-keys into another team's free
range, as it always did at 70). In dynasty, `GameCheckRosterCutState` checks position minimums only (`0x48fefc`);
`CanAdvanceToOffseason` (`0x250ad8 -> 0x1faa08`) reads options tables. Grade thresholds, Heisman ratings and coach
contract tiers also compare with 69/70 and were excluded by reading each function.

Still open: the `.team` package the console uploads every week keeps `PLAY 0/70` (and `DCHT 91`, `CUTP 70`, `PINP 840`,
`CAMW 200`, `PLSU 50`, `TRAN 23`, `PLSS 23`, `PINT 65`, `RECB 35`, `RCPR 25`, `RCPT 25`, `RECV 35`, `USDT 16`): per-team

## Mode databases: the 9,100-row player template (2026-11-07)

The 90-man FCS 2026 roster file (11,306 PLAY rows, max 13,000) loaded in the Rosters screens with every team past
physical row 9,100 empty. Not the save buffer (already 0x1c0000): the game loads a roster file as the `LEAG` database
with the file's own table sizes (`0x21be68`: image load `0xa5da0c`, register `0xa59230`), but each mode database is
built from templates in the standard-data database `STDA` (`0x44768c` walks the template list; `0x447320` runs
`use 'ADTS' select into <db>.<table> * from <table>` per table) and is then filled from `LEAG` team by team
(`0x4f3d88` -> `0x4e9984` -> `0x44a6f0`, record copies through the table map at `0x1c867bc`). The copy stops silently
when the mode PLAY table is full, and the PLAY template holds 9,100 rows (130 x 70). ROST (Rosters, `0x4f3ff0` /
`0x4f4540`), DYND (dynasty, `0x4f5d40` / `0x4f7fa0`) and EXHI (Play Now, `0x4f0818` / `0x4f0a64` / `0x4f1248`) are all
built this way; the online dynasty file is loaded as an image, which is why a re-keyed 13,000-row dynasty was never
affected.

DB library table struct (`0xa4f000`-`0xa6b000`): +0 name (4CC as in SQL text, PLAY = `0x59414c50` 'YALP'), +4 max
records (u16), +6 field count, +8 owning DB (DB +0x1c byte 1 = read-only / asset DB), +0xc record length, +0x10 next
table, +0x24 record storage, +0x30 flags, +0x4c grown maximum. `0xa51750(db, name)` finds a table; `0xa56dbc(table,
rows)` resizes one (refuses read-only DBs with 0x1f, malloc when max is 0 else realloc rows x length, stores rows at +4
and +0x4c, returns 0 or 2); the game uses it itself before bulk copies (`0x3046e4`).

Third entry **"FCS mod: 100-player rosters (player table)"** (`spike/blaze/tools/roster-table-patch.py`, v2, 35
words). v1 resized PLAY inside the template copier `0x447320` and changed nothing in game: the ROST player table does
not come through that copier. v2 grows PLAY in the finished database right before its indexes are built:

| what | sites | replacement |
|---|---|---|
| Rosters builder `0x4f3ff0`: `bl 0x4f237c` (create ROST indexes) at `0x4f417c` | 1 | `bl` stub at `0x1678cec` (r3 = ROST, r11 = `0x4f237c`) |
| new-dynasty builder `0x4f5d40`: `bl 0x4f4e44` (PLAY index prep) at `0x4f5e9c` | 1 | `bl` stub at `0x69a9fc` (r3 = DYND, r11 = `0x4f4e44`) |
| shared routine (`0x13b4b40`, 14 of 15 padding words) | 14 | `FindTable 0xa57d68(db, 'YALP')`; skip if missing or >= 13,000; else jump to the resize |
| shared routine (`0x16367a4`, 9 of 11 padding words) | 9 | `TableResize 0xa56dbc(table, 13000)`; restore the frame; tail-call the original through CTR |

The insert path checks the maximum this resize sets (`0xa56f94`: free-list slot, else `+0x4e < +4`, else 0x13), and
the indexes are built after it. All four code locations are the only provably unused inter-function padding runs in
.text (filler words only, a function end before, a prologue after, nothing branches to or addresses them). Play Now
(EXHI) fills the same way and is not covered yet. `ps3-eboot.mjs --roster-table` bakes it after the capacity words.

at 90; save to a new slot and read it back (PLAY 13000, 11,306 rows); an offline dynasty from it; a new online

## League totals above 8,820 players (2026-11-07)
